## Backlog — deferred from C1 (ADR-0004)

Sink-owned checkpoint mode and explicit start positions were scoped in the C1 design (§ Scope item 7) and **deferred by user decision** (2026-07-21); C1 refuses them fail-closed today. Authored facts only; status is DERIVED.

| ID | What | Acceptance | Depends | Why |
|---|---|---|---|---|
| C1a | **Sink-owned checkpoint mode** — the sink persists the processed position atomically with its own data write and hands it back via `Capstan.Sink.checkpoint/0` (effect-once on the atomic path). Refused today as `:sink_owned_mode_unsupported`. slug:c1-sink-owned-checkpoint | A sink-owned pipeline runs: `AssemblerServer` reads the resume position from `Sink.checkpoint/0`, delivers, and the sink checkpoints atomically with its own write; a kill/restart replays zero and skips zero (effect-once), proven live on an append-only ledger | C1 | [ADR-0004](adr/0004-c1-scope-lib-owned-checkpoint-only.md). The `Capstan.Sink` behaviour and `Capstan.Pipeline` per-mode validation already exist; only the `AssemblerServer` run-path wiring is owed |
| C1b | **Explicit start positions** — honor `start_position:` as an explicit `%Capstan.Position{}` override and as `:current`, end-to-end. Refused today as `:start_position_override_unsupported` / `:start_position_current_unsupported`. slug:c1-explicit-start-position | A pipeline started with an explicit `%Position{}` resumes the `Connection` dump AND seeds the `AssemblerServer` watermark from the SAME position (no silent checkpoint hole); `:current` starts from the server's live position via a pre-connect query | C1 | [ADR-0004](adr/0004-c1-scope-lib-owned-checkpoint-only.md). The spine threads a position to the `Connection` dump, but the `AssemblerServer` seeds its watermark from the checkpoint store alone today — honoring an override needs both to agree |

| ID | What | Acceptance | Depends | Why |
|---|---|---|---|---|

Refused today as `:snapshot_pk_unsupported_type`. slug:c2-collation-string-pk | A collation-string-PK table backfills gap-free/dup-free: the cursor-gate's `k ≤ cursor` comparison reproduces the source's collation order (not Elixir byte-order) so no row is mis-classified | C2 | [ADR-0005](adr/0005-initial-snapshot-cursor-gate-brief-lock.md). ## C3-forward couplings (implementation notes, not backlog rows).

Two C1 sites are correct today but coupled to C3's `changes`-as-lazy-enumerable / a future multi-output assembler; each carries an inline guard comment:

- `lib/capstan/assembler_server.ex` — the filtered/empty dispatch matches `changes` as a concrete `[]`. When C3 makes `changes` a lazy single-pass enumerable, an empty `Stream` would not match `[]`; the Assembler must then emit an explicit filtered/empty signal rather than have this site infer it from the representation (`Enum.empty?/1` would consume a single-pass reader).
- `lib/capstan/assembler_server.ex` — DDL delivery reads the assembler's **post-step** position, exact only because `Assembler.step/2` emits at most one output per event in C1. A future multi-output step must carry a per-output position, or the watermark could advance past undelivered work (an effect-once violation).
